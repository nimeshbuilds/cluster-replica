# Replicove support

Replicove is maintained in public by Nimesh Builds and is experimental. Community support is best effort; no response-time or production-support guarantee is offered.

| Need | Where to go |
| --- | --- |
| Setup help, ideas, or an integration-testing workflow | [GitHub Discussions](https://github.com/nimeshbuilds/replicove/discussions) |
| A reproducible defect or feature proposal | [Issue templates](https://github.com/nimeshbuilds/replicove/issues/new/choose) |
| A security vulnerability | [Private vulnerability report](https://github.com/nimeshbuilds/replicove/security/advisories/new); see [Security](SECURITY.md) |
| Implementation and compatibility status | [Project status](docs/project-status.md) and [roadmap](ROADMAP.md) |
| Community conduct | [Code of conduct](CODE_OF_CONDUCT.md) |

Include the commit or branch, host and guest Kubernetes versions, vCluster profile, expected behavior, and the smallest sanitized reproduction. Remove credentials, kubeconfigs, Secret data, account identifiers, and private infrastructure details before sharing logs or YAML.

For behavior reproduced directly with upstream vCluster, consult the [upstream documentation](https://www.vcluster.com/docs) and [upstream issue tracker](https://github.com/loft-sh/vcluster/issues). Explain whether Replicove is required to reproduce it.
